## NotificationsApp

Микросервисный сервис отправки уведомлений по нескольким каналам (e‑mail, SMS, push), реализованный в рамках учебного задания по курсу «Разработка микросервисов». Система использует RabbitMQ для асинхронного взаимодействия сервисов и PostgreSQL для хранения состояния отправленных уведомлений, а также ELK для логирования.

### Структура проекта

- **`ApiGateway`** – шлюз уведомлений (Notification Gateway)
  - ASP.NET Core Web API, единая точка входа для внешних систем.
  - Принимает HTTP‑запросы на отправку уведомлений, валидирует данные.
  - Использует `RabbitMqModule` и RPC‑клиентов для маршрутизации запросов в микросервисы каналов (email, sms, push).
  - Через `DAL` и PostgreSQL хранит состояние уведомлений (успех/ошибка/повторы).
  - Логирует операции с помощью Serilog в Elasticsearch (просмотр через Kibana).

- **`EmailNotificator`** – сервис отправки e‑mail
  - .NET Worker‑сервис (фоновый `HostedService`).
  - Получает запросы на отправку по RPC от `ApiGateway` через RabbitMQ.
  - Формирует и отправляет письма с использованием MailKit/SMTP.
  - Возвращает результат в `ApiGateway` (успех/ошибка) для фиксации статуса.

- **`SmsNotificator`** – сервис отправки SMS
  - Worker‑сервис, интеграция с провайдером MainSMS.
  - Обрабатывает RPC‑запросы от `ApiGateway` через RabbitMQ.
  - Отправляет SMS и возвращает статус отправки.

- **`PushNotificator`** – сервис отправки push‑уведомлений
  - Worker‑сервис, интеграция с PushBullet.
  - Получает RPC‑запросы от `ApiGateway` через RabbitMQ.
  - Отправляет push‑уведомления и возвращает результат.

- **`RabbitMqModule`** – общий модуль работы с брокером сообщений
  - `Common` – провайдер подключения к RabbitMQ и базовые настройки.
  - `RpcClient` / `RpcServer` – реализация RPC‑взаимодействия (запрос‑ответ) между `ApiGateway` и нотификаторами.
  - Используется во всех сервисах, обеспечивая единый подход к обмену сообщениями.

- **`DAL`** – уровень доступа к данным
  - `NotificationStatusDbContext` (EF Core) и репозиторий `INotificationStatusRepository`.
  - Хранение статусов уведомлений (успешно/ошибка/повторная попытка) в PostgreSQL.
  - Используется `ApiGateway` для аудита и запросов статуса.

- **`Core`** – общие доменные модели и контракты
  - Модели уведомлений и базовые типы, используемые всеми сервисами.
  - Обеспечивает единый контракт между шлюзом и микросервисами каналов.

### Соответствие ключевым пунктам ТЗ

- **Архитектура системы**: микросервисная; отдельные сервисы по каналам (`EmailNotificator`, `SmsNotificator`, `PushNotificator`), входная точка – `ApiGateway`, общий модуль работы с брокером – `RabbitMqModule`, хранение состояния – `DAL` + PostgreSQL.
- **Шлюз уведомлений (Notification Gateway)**: реализован в `ApiGateway`, принимает REST‑запросы, маршрутизирует их через RabbitMQ/RPC в соответствующий канал и обновляет статус уведомления в базе.
- **Микросервисы каналов**: три независимых background‑сервиса для email/SMS/push, каждый можно масштабировать отдельно без изменения других.
- **Очереди сообщений**: используется RabbitMQ, обмен по RPC‑паттерну (`RabbitMqModule.RpcClient`/`RpcServer`), что обеспечивает асинхронность и возможность повторов/восстановления соединений.
- **Управление состоянием**: статусы уведомлений и информация о попытках отправки сохраняются в PostgreSQL через `NotificationStatusDbContext` и репозиторий `INotificationStatusRepository`, что позволяет организовать мониторинг состояний отправки.
- **API**: `ApiGateway` предоставляет REST API для создания уведомлений и получения статуса; тип канала (email/sms/push), получатель и текст передаются через HTTP‑запрос.
- **Конфигурация и расширяемость**: добавление нового канала сводится к созданию нового worker‑сервиса, использующего `RabbitMqModule`, и подключению нового RPC‑клиента/сериализатора в `ApiGateway`.
- **Мониторинг и логирование**: логирование реализовано через Serilog c отправкой логов в Elasticsearch; стек ELK (Elasticsearch + Kibana + Logstash) и вся инфраструктура (RabbitMQ, PostgreSQL, микросервисы) поднимаются через `docker-compose.yml`.
- **Контейнеризация и масштабируемость**: для `ApiGateway` и каждого нотификатора есть отдельный `Dockerfile`, сервисы, брокер, БД и ELK запускаются в Docker‑контейнерах и могут масштабироваться независимо.
